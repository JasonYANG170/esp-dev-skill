# AGENTS.md — Supplementary Agent Guide

> Core rules, recipe index, pitfalls, and execution workflow are all in `SKILL.md`.
> This file covers **only** conventions and tooling guidance not present in `SKILL.md`. Do not duplicate content.

## Project Context

**Language**: C++ (`.cpp` for `app_main`/drivers, `.h` for headers; the SDK itself is C++ over a C ESP-IDF base) · **Target**: ESP32 family SoCs · **Toolchain**: ESP-IDF v5.5.4 (`idf.py`), GCC for Xtensa/RISC-V. The Matter core comes from the pinned `connectedhomeip` submodule (`107f97a9813`).

## Code Generation Conventions

### File Naming
- Application entry: `main/app_main.cpp` (always `extern "C" void app_main()`).
- Application driver: `main/app_driver.cpp`, private header `main/app_priv.h`.
- Reset/button helpers: `main/app_reset.cpp` / `app_reset.h` (from `examples/common`).
- Cluster XML for custom clusters: `zap-templates/` area, registered in `zcl.json`.
- Manufacturing / factory data: generated by `esp-matter-mfg-tool` into `out/<vid>_<pid>/<uuid>/`.

### Include Pattern (device firmware)
```cpp
#include <esp_err.h>
#include <esp_log.h>
#include <nvs_flash.h>

#include <esp_matter.h>           // pulls in data model + core
#include <esp_matter_console.h>   // optional: CONFIG_ENABLE_CHIP_SHELL
#include <esp_matter_ota.h>       // optional: CONFIG_ENABLE_OTA_REQUESTOR

#include <app_priv.h>
#include <app_reset.h>
#if CHIP_DEVICE_CONFIG_ENABLE_THREAD
#include <platform/ESP32/OpenthreadLauncher.h>
#endif
#include <app/server/Server.h>
#include <app/server/CommissioningWindowManager.h>

using namespace esp_matter;
using namespace esp_matter::attribute;
using namespace esp_matter::endpoint;
using namespace chip::app::Clusters;   // gives OnOff::Id, LevelControl::Id, etc.
```

### Standard Example Project Structure
```
my_matter_device/
├── main/
│   ├── CMakeLists.txt          # idf_component.yml often lives here

```

### Canonical `app_main` Pattern
```cpp
extern "C" void app_main()
{
    esp_err_t err = ESP_OK;
    nvs_flash_init();                                  // (1) NVS first

    app_driver_handle_t light_handle = app_driver_light_init();      // (2) driver
    app_driver_handle_t button_handle = app_driver_button_init();
    app_reset_button_register(button_handle);

    node::config_t node_config;                        // (3) node
    node_t *node = node::create(&node_config, app_attribute_update_cb, app_identification_cb);

    extended_color_light::config_t light_config;       // (4) endpoint(s)
    light_config.on_off.on_off = DEFAULT_POWER;
    light_config.level_control.current_level = DEFAULT_BRIGHTNESS;
    endpoint_t *endpoint = extended_color_light::create(node, &light_config,
                                                        ENDPOINT_FLAG_NONE, light_handle);
    light_endpoint_id = endpoint::get_id(endpoint);

#if CHIP_DEVICE_CONFIG_ENABLE_THREAD                   // (5) optional Thread platform cfg
    esp_openthread_platform_config_t config = {
        .radio_config = ESP_OPENTHREAD_DEFAULT_RADIO_CONFIG(),
        .host_config  = ESP_OPENTHREAD_DEFAULT_HOST_CONFIG(),
        .port_config  = ESP_OPENTHREAD_DEFAULT_PORT_CONFIG(),
    };
    set_openthread_platform_config(&config);
#endif

    err = esp_matter::start(app_event_cb);             // (6) start
    ABORT_APP_ON_FAILURE(err == ESP_OK, ESP_LOGE(TAG, "Failed to start Matter"));

    app_driver_light_set_defaults(light_endpoint_id);  // (7) apply defaults to HW

#if CONFIG_ENABLE_CHIP_SHELL                           // (8) optional console
    esp_matter::console::init();
#endif
    while (true) { vTaskDelay(10000 / portTICK_PERIOD_MS); }
}
```

### Attribute-Update Callback Pattern
```cpp
static esp_err_t app_attribute_update_cb(attribute::callback_type_t type, uint16_t endpoint_id,
                                         uint32_t cluster_id, uint32_t attribute_id,
                                         esp_matter_attr_val_t *val, void *priv_data)
{
    esp_err_t err = ESP_OK;
    if (type == PRE_UPDATE) {                          // only act before the value lands
        err = app_driver_attribute_update(priv_data, endpoint_id, cluster_id, attribute_id, val);
    }
    return err;                                        // ESP_OK for unhandled attrs
}
```

### Logging Convention
```cpp
static const char *TAG = "app_main";
ESP_LOGI(TAG, "Light created with endpoint_id %d", light_endpoint_id);
ESP_LOGE(TAG, "Failed to start Matter, err:%d", err);
```
The SDK also offers `ABORT_APP_ON_FAILURE(cond, log_stmt)` (from `common_macros.h`) used throughout the examples.

## Build Workflow

1. **One-time environment** (each new terminal):
   ```bash
   cd esp-idf; source ./export.sh; cd ..
   cd esp-matter; source ./export.sh; cd ..
   export IDF_CCACHE_ENABLE=1   # Matter builds are slow; ccache helps a lot
   ```
2. **Set target & build**:
   ```bash
   cd examples/light
   idf.py set-target esp32c3   # or esp32, esp32c6, esp32h2, ...
   idf.py build
   ```
3. **Flash** (first time, wipe storage):
   ```bash
   idf.py erase_flash flash monitor
   ```
4. **Commission & control** from host:
   ```bash
   chip-tool interactive start
   # in the interactive prompt:
   pairing ble-wifi 0x7283 <ssid> <passphrase> 20202021 3840
   onoff toggle 0x7283 1
   ```

## Code-Generation Checklist (Device Firmware)

- [ ] `nvs_flash_init()` is the first call in `app_main`
- [ ] `node::create()` is called with both `app_attribute_update_cb` and `app_identification_cb`
- [ ] Application endpoints are created **before** `esp_matter::start()`
- [ ] `app_attribute_update_cb` only acts on `PRE_UPDATE` and returns `ESP_OK` for unhandled attributes
- [ ] Driver handle passed as `priv_data` to `<device_type>::create()` and cast back in the callback
- [ ] Sensor/async writes use `attribute::update()` (not `set_val`), scheduled via `ScheduleLambda` from non-Matter tasks
- [ ] `esp_matter::start(app_event_cb)` is called exactly once
- [ ] Console commands registered only when `CONFIG_ENABLE_CHIP_SHELL=y`
- [ ] Thread platform configured before start when `CHIP_DEVICE_CONFIG_ENABLE_THREAD`
- [ ] Commissionable/DAC provider choice matches whether a factory partition is flashed
- [ ] On esp32c5/c6: exactly one of Wi-Fi / Thread is fully configured (mdns/openthread/wifi-station options agree)

## Do Not Modify

- `connectedhomeip/connectedhomeip/` — the upstream Matter SDK; treat as read-only and rebuild host tools from here
- `components/esp_matter/` — the esp-matter SDK; copy patterns from it but do not edit in place
- Generated data-model code under `components/esp_matter/data_model/generated/` — produced by ZAP; edit the XML/templates and re-run `zap_regen_all.py` instead
- `SKILL.md` front matter — Skill metadata

## Host-Tool Notes

- `chip-tool` is built by `install.sh` and lives in `connectedhomeip/connectedhomeip/out/host`. Add it to `PATH` for convenience.
- `chip-cert` (for generating test Certification Declarations) is in the same `out/host` directory.
- `esp-matter-mfg-tool` is a separate Python package from `esp-matter-tools`; install it to generate factory partitions.
- To regenerate data-model code after editing a cluster XML: `cd connectedhomeip/connectedhomeip && source ./scripts/activate.sh && ./scripts/tools/zap_regen_all.py`.
